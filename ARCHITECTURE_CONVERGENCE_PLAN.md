# Architecture convergence plan

**Status: Phase 0 and Phase 1 only. The migration is not complete, and
nothing in this document claims it is.** No scientific model was deleted or
moved in this tranche. The QTA hardware ontology is still present, still
enforced where it was enforced, and still on the CI path.

Companions: `FILE_DISPOSITION.csv` (one disposition per tracked file) and
`DEPENDENCY_CUTOVER.md` (what reaches what, measured, and the cut order).

## 1. Target

The repository holds two systems that grew into each other: a governed
scientific-agent substrate (`qta_agent/`) and a cryogenic-apparatus theory
with its gates, machine FSM, BOM and output contract. The target keeps the
first, keeps the physics and the scientific method of the second, and
retires the apparatus as an authority:

```
AI proposes                          qta_agent/agents.py, context.py, memory.py
  -> event-sourced governed execution  events, tasks, scheduler, capability, tools, execution
  -> deterministic scientific computation   ScientificModel plugins            (Phase 2+)
  -> ResultBundle                                                              (Phase 2)
  -> independent numerical / invariant verification   VerificationResult; reconstruct,
                                        separate_verify, FEniCSx, reduction checks
  -> evidence                          evidence.py (content-addressed)
  -> authority decision                authority.py + store.py
```

*AI proposes, deterministic computation executes, independent verification
decides.* No component may propose a result, execute ungoverned change, and
certify its own output.

## 3. Dispositions

The directive names eight dispositions and does not define them. The
definitions used in `FILE_DISPOSITION.csv`:

| disposition | means | acted on |
|---|---|---|
| `KEEP_AS_IS` | generic already; no QTA coupling found; no change planned | -- |
| `KEEP_AND_HARDEN` | kept, and changed for a trust or correctness defect (this tranche) or scheduled for one | Phase 1 / ongoing |
| `EXTRACT_GENERIC` | reusable scientific infrastructure to move into the generic core unchanged in meaning | Phase 3 |
| `KEEP_AS_MODEL_PLUGIN` | a physics model (or its reference data / docs / tests) that stays as a replaceable plugin behind `ScientificModel` | Phase 4 |
| `REWRITE_GENERIC` | a capability worth keeping whose current form is bound to the QTA apparatus, gate model or output contract | Phases 2-7, per row |
| `REGENERATE` | a derived artefact kept in the tree and regenerated by tooling whenever its inputs change | every change; new set in Phase 7 |
| `RETIRE_TO_HISTORY` | QTA hardware ontology, its data, tests that protect only it, and material already historical | Phase 5 (history stays in git and `attic/`) |
| `DELETE_GENERATED_AND_REBUILD` | a model output of the QTA pipeline under the old output contract, to be rebuilt by the generic workflow and not carried forward by hand | Phases 6-7 |

**How rows were assigned.** By an explicit rule table (one glob per rule,
first match wins), each rule carrying its rationale and evidence, in
`tools/file_disposition.py`, which **fails** when a file matches no rule and
when a rule matches no file. There is no fallback, so there is no
miscellaneous bucket to hide in: the first run refused three fuzz-corpus
files nobody had written a rule for. `tests/test_file_disposition.py` holds
the committed CSV to the rules' output for the tree as it is, so a file
added later without a disposition fails the suite instead of going
unclassified. Evidence is of
four kinds: the AST import graph (`DEPENDENCY_CUTOVER.md`), the committed
regeneration set (`hdf5_output_mapping.json`, which records the 88 outputs
`qta_full_sim.py` writes), each module's own docstring read in full, and --
only as a pointer to what to read -- a census of hardware vocabulary. The
census was not used to classify: it counts `JobState.BLOCKED` in the
scheduler as a QTA gate.

Two rules worth stating because a reader might expect otherwise:

* **A test follows its subject.** Tests of retired hardware invariants are
  `RETIRE_TO_HISTORY` and will be retired deliberately, with the reason
  written down, when their subject goes (directive s26). Tests of trust or
  scientific invariants are kept even where their subject is rewritten.
* **Generated outputs are not edited now.** Every `DELETE_GENERATED_AND_REBUILD`
  file stays byte-gated and untouched until the generic workflow can rebuild
  its replacement (directive s25, Phase 0 rule 3).

**C. Retired QTA hardware ontology (RETIRE_TO_HISTORY):** `machine_fsm`,

Everything that mixes B with C -- the orchestrators, campaign continuity,

builders -- is `REWRITE_GENERIC`, because it holds a capability the directive
keeps in a form it retires.

## 5. State machines

Retained, each owning its lifecycle and derived from the log:

| domain | module | states |
|---|---|---|
| authority | `authority.py`, `store.py` | PROPOSED, UNDER_REVIEW, VERIFIED, PROMOTED, STALE, SUPERSEDED, REVOKED, REJECTED |
| tasks | `tasks.py` | CREATED, VALIDATED, QUEUED, LEASED, EXECUTING, COMPLETED, FAILED, TIMED_OUT, CANCELLED, VERIFIED, REJECTED |
| jobs | `scheduler.py` | WAITING, READY, DISPATCHED, RETRY_WAIT, SUCCEEDED, FAILED, BLOCKED, CANCELLED, INVALIDATED |
| memory | `memory.py` | ACTIVE, STALE, SUPERSEDED, RETRACTED |

Retired: the physical machine FSM (`machine_fsm.py`) only. To add: a
hypothesis lifecycle (PROPOSED ... RETRACTED) in which the proposing agent
cannot move its own hypothesis to SUPPORTED (directive s22), in a later
phase.

## 6. Phase 1 -- trust-boundary defects (this tranche)

Recorded in `docs/DEFECT_LEDGER.md`; summarized in the tranche report.

* **D-2026-70 -- verify-then-read, repository-wide.** 17 sites verified one
  read of the log and folded another -- 15 reducer loads, catch-up fallbacks
  and reconstructions; `EventLog.advance` itself; `AuthorityStore.load_from`
  -- plus 3 helpers in `governed_stage10` that read with no verification at
  all. All now fold the single verified read; the primitives return the
  verified prefix only.
* **D-2026-71 -- reducer identity.** A projection snapshot names its reducer
  (kind, id, declared version, source-closure digest, schema version); a
  checkpoint from other code is replayed from genesis, never restored.
* **D-2026-72 -- context provenance.** A summary must name a source item that
  exists and the digest of that item's exact bytes; the builder no longer
  invents an omission (tier guessed, digest `""`, length 0) for a source it
  was never given, and the manifest reader refuses one.
* **D-2026-73 -- enforcement asserts.** The ten machine interlocks in
  `qta_full_sim.py` were `assert` statements and vanished under `python -O`;
  they raise explicitly now. The guard that was meant to stop this scanned
  three directories (not the root) and compared a set of files where its
  docstring said it pinned a count; it scans every production file and pins
  per-file counts now.

## 7. Phase 2 -- the minimal generic interfaces

What Phase 2 must introduce, and nothing more; typed, Pydantic where a
boundary validates input, no inheritance hierarchy forced on existing
solvers.

| interface | minimum content | why this and not less |
|---|---|---|
| `ScientificModel` (protocol) | `model_id`, `model_version`, `implementation_digest` (the same source-closure digest as reducer identity), parameter schema, `validate(inputs)`, `run(inputs, config) -> ResultBundle`, result schema, declared invariants, applicability domain, supported independent checks, provenance description | the agent must not know the numerics and the model must not know the agent; this is the whole contract between them |
| `ModelRegistry` | register / look up by `(model_id, model_version)`; refuses a second registration of the same identity with a different digest | replaces physical-component authority; SALib, OpenMDAO, Monte Carlo and Snakemake integrate here |
| `ResultBundle` | model identity + implementation digest; input/parameter digest; environment digest; seeds; solver configuration; outputs **with units**; convergence diagnostics; invariant results; warnings; failed/undefined outputs stated as such; artefact references (HDF5 by digest, never arrays in the log); provenance | the one thing that crosses from computation into evidence |
| `VerificationResult` | which check, of which bundle (by digest), by which implementation (must differ from the producer's `implementation_digest` when the check claims independence), verdict, measured value, criterion and its derivation | "independent" becomes a checkable field instead of a word |
| `Observation` | kind in {RAW_OBSERVATION, PROCESSED_OBSERVATION, SYNTHETIC_OBSERVATION, SIMULATION_RESULT, DERIVED_STATISTIC, CALIBRATED_PARAMETER}; source, transformation, calibration and uncertainty provenance | a simulation must never silently become a measurement; the kind is a type, not a label |
| run identity | digest over model identity, implementation digest, parameter digest, environment digest, seeds, workflow revision, upstream evidence digests | integrates with `idempotency.py`; an identical verified run is reused by evidence, never recomputed blindly or trusted by name |

**Proving case: thermal 1D.** `solve_thermal_1d(cfg, ...) -> Thermal1DResult`
is adapted, not rewritten. Its declared invariants already exist as code in
`verification.py`: source energy integral, Kapitza sign, 1D mesh
convergence, diffusion sanity. Its independent check exists too:
`reduction_2d_to_1d` solves the same boundary-value problem with the 2D
axisymmetric discretization -- a second implementation, not a second call
into the first -- and FEniCSx is staged as a third. The adapter's exit
criterion: a `ResultBundle` whose invariant results and independent
verification are produced by those existing checks, submitted as evidence
through the governed path, with no QTA module in `sys.modules` after
importing it (which requires cut C1: today importing `thermal_1d` loads the
gate-spec assembly through the package `__init__`).

**Invariants that hold across every phase.** The event log stays the only
authority; checkpoints and projections accelerate it and never replace it.
Independent verification is never a second call into the producing
implementation. AI-generated content never certifies itself. Simulation is
never labelled measurement. No tolerance is widened to make a test green.
**PASS=0 and `measured_in_this_system=false` stay enforced until the gate and
release model that needs them is replaced (Phases 6-7)** -- retiring a claims
check before retiring the claims it guards would open exactly the window the
directive exists to close.
