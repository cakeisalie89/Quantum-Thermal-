# results_gate_table.csv — Gate Table (single source of truth)

`results_gate_table.csv` is generated by `qta_full_sim.py` and is the **only**
source of truth for gate counts. The manuscript and all summaries must agree with
it; `manuscript_consistency_check.py` fails if they do not.

## Canonical counts (computed from the file)
83 total | PASS=0 CONDITIONAL=47 BLOCKED=23 UNKNOWN=2 DERIVED_CHECK=11 FAIL=0

Allowed `status` values: `BLOCKED`, `CONDITIONAL`, `UNKNOWN`,
`DERIVED_CHECK`, `FAIL`, `PASS`. **`PASS` is never produced**: every gate has
`measured_in_this_system = false` and `can_PASS_now = NO` (forecast-only).

## Columns
`gate_id, mode, name, equation, computed, threshold, unit, status, reason, fix,
measured_in_this_system, source_directness, can_PASS_now, required_measurement,
blocked_by, notes`.

## Status axes (do not conflate)
- **Evidence:** ASSUMED, UNKNOWN, MANUFACTURER_SPEC, LITERATURE_BOUND,
  DESIGN_SPECIFIED, MEASURED_EXTERNAL, MEASURED_IN_SYSTEM.
- **Implementation:** NOT_INSTALLED, INSTALLED_NOT_TESTED, TESTED, VERIFIED.
- **Gate verdict:** BLOCKED, CONDITIONAL, UNKNOWN, DERIVED_CHECK, FAIL, PASS.

A component may be DESIGN_SPECIFIED (evidence) and NOT_INSTALLED (implementation)
at the same time; this is not a contradiction.
